## Conventions

- **Base URL:** `http://localhost:3000` in development (`PORT` changes the port). All endpoints are under `/api`.
- **Bodies** are JSON. Send `Content-Type: application/json`; a body sent as anything else is treated as missing and fails validation. Bodies over 100 kB get a 413.
- **Ids** are UUID strings, generated by the server.
- **Timestamps** are ISO 8601 strings in UTC, such as `"2026-11-02T11:18:50.876Z"`.
- **Unknown fields are rejected.** Every body and list query is checked against a strict schema, so a field the endpoint doesn't accept, including server-owned ones like `id`, `createdAt` and `orderIndex`, is a 400.
- **Numbers must be JSON numbers.** `"2"` is rejected where `2` is expected.
- **No authentication.** Access is controlled by the network: localhost in development, Tailscale from Phase 2.
- **CORS:** browsers may call the API from another origin only if it's listed in `CORS_ORIGINS` (comma-separated). By default no other origin is allowed. Allowed origins can also read the `X-Total-Count` header.

### Recipe

```json

  "name": "Beef Chili",
  "description": "Chilli con Carne using Beef mince and bacon lardons",
  "servings": 2,
  "prepTime": 20,
  "cookTime": 120,
  "instructions": "1. Put the Beef stock pot in a jug…",
  "createdAt": "2026-11-02T11:18:50.876Z",
  "updatedAt": "2026-11-02T11:18:50.876Z",
  "recipeIngredients": [
    {
      "id": "5c0e4a3b-6a8f-4b8e-9f3c-1d2e3f4a5b6c",
      "recipeId": "09b75162-d37f-476c-b87a-30bbba971058",
      "ingredientId": "3308532b-ec81-4c05-9def-8cd595f0f035",
      "orderIndex": 0,
      "quantity": 1,
      "quantityMax": null,
      "unit": null,
      "note": "diced",
      "ingredient": {
        "id": "3308532b-ec81-4c05-9def-8cd595f0f035",
        "name": "onion",
        "createdAt": "2026-11-02T11:18:50.876Z",
        "updatedAt": "2026-11-02T11:18:50.876Z"
      }
    }
  ]
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID) | |
| `name` | string | 1–200 characters, stored trimmed |
| `description` | string or null | |
| `servings` | integer | At least 1. Defaults to 1 |
| `prepTime`, `cookTime` | integer or null | Minutes, 0 or more |
| `instructions` | string or null | Plain text |
| `createdAt` | timestamp | |
| `updatedAt` | timestamp | Changes on every PATCH, including one that only changes the lines |
| `recipeIngredients` | array of lines | Always included, sorted by `orderIndex` |

### Ingredient line

One line of a recipe's ingredient list. In responses each line includes its `ingredient`.

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID) | |
| `recipeId` | string (UUID) | |
| `ingredientId` | string (UUID) | |
| `orderIndex` | integer | Position in the recipe, from 0. Set by the server from the order of the array you send |
| `quantity` | number or null | Greater than 0. Null means "to taste" or unspecified |
| `quantityMax` | number or null | Upper end of a range ("2–3"). Only set when `quantity` is |
| `unit` | string or null | A canonical unit symbol (see [Units](#units)). Null means a count, as in "3 eggs" |
| `note` | string or null | Preparation, such as "finely diced". Up to 200 characters |
| `ingredient` | Ingredient | Responses only |

The same ingredient may appear on more than one line.

## Lists, search and pagination

`GET /api/recipes` and `GET /api/ingredients` take the same query parameters:

| Parameter | Default | Rules |
|---|---|---|
| `search` | none | Fuzzy match on the name. Trimmed; at most 100 characters; blank means no search |
| `limit` | `50` | Page size: a whole number from 0 to 100 |
| `offset` | `0` | How many items to skip: a whole number, 0 or more |

- **Response:** a JSON array (possibly empty) and an `X-Total-Count` header with the number of items, or of search matches, across all pages. `limit=0` returns an empty array, so it gives you just the total.
- **Order:** plain lists by name, then id. Search results by how well they match, then name, then id. The order is stable, so paging with `offset` never repeats or skips an item.
- **Search** matches names that are similar to the term (PostgreSQL trigram `word_similarity` above 0.3), which tolerates typos ("beff" finds "Beef Chili"), or that contain it, ignoring case. `%`, `_` and `\` match literally.
- **Each parameter once.** A repeated parameter (`?search=a&search=b`) or an unknown one (`?serach=beef`) is a 400.

With the sample data loaded:

```http
GET /api/ingredients?search=pepper&limit=1

HTTP/1.1 200 OK
X-Total-Count: 2

[{ "id": "…", "name": "cayenne pepper", … }]
```

Both peppers match equally well, so they're ordered by name; `offset=1` returns `red pepper`.

## Health

### `GET /api/health`

Runs `SELECT 1` against the database.

| Status | Body |
|---|---|
| 200 | `{ "status": "ok" }` |
| 503 | `{ "status": "error" }` when the database can't be reached. The reason goes only to the server log |

## Recipes

### `GET /api/recipes`

Lists recipes, each with its lines. Takes `search`, `limit` and `offset` (see [Lists](#lists-search-and-pagination)).

**Responses:** 200 with an array of [Recipe](#recipe) and `X-Total-Count`; 400 for a bad query.

### `GET /api/recipes/:id`

**Responses:** 200 with the [Recipe](#recipe); 404 `{ "error": "Recipe not found." }`.

### `POST /api/recipes`

Creates a recipe and its lines in one write.

| Field | Required | Rules |
|---|---|---|
| `name` | yes | String, 1–200 characters after trimming |
| `description` | no | String or null |
| `servings` | no | Integer, at least 1. Default 1. Not null |
| `prepTime`, `cookTime` | no | Integer, 0 or more, or null |
| `instructions` | no | String or null |
| `ingredients` | no | Array of lines, in recipe order. Default: none |

Each line in `ingredients`:

| Field | Required | Rules |
|---|---|---|
| `ingredientId` | yes | UUID of an existing ingredient |
| `quantity` | no | Number greater than 0, or null. Absent means null |
| `quantityMax` | no | Number or null. Only allowed with `quantity`, and at least `quantity` |
| `unit` | no | A unit symbol or alias (see [Units](#units)), converted to the symbol. Null, absent or blank means a count |
| `note` | no | String of up to 200 characters, or null |

```http
POST /api/recipes
Content-Type: application/json

{
  "name": "Garlic Soup",
  "servings": 2,
  "ingredients": [
    { "ingredientId": "3308532b-ec81-4c05-9def-8cd595f0f035", "quantity": 2, "note": "sliced" },
    { "ingredientId": "60c501d9-706a-40b8-813d-5475a6ee1406", "quantity": 6, "unit": "cloves" },
    { "ingredientId": "31058cf2-6901-4ea4-afe7-c98c21e27752", "quantity": null, "note": "to taste" }
  ]
}
```

The second line is stored with `"unit": "clove"`, and the lines get `orderIndex` 0, 1 and 2.

**Responses:**
- 201 with the created [Recipe](#recipe)
- 400 `{ "error": "Validation failed.", "fields": { … } }` for a rule above
- 400 `{ "error": "One or more ingredient IDs are invalid." }` when an `ingredientId` is a valid UUID but no such ingredient exists

### `PATCH /api/recipes/:id`

Changes only the fields in the body; the rules are the same as for POST, but every field is optional. An empty body changes nothing except `updatedAt`.

`ingredients` works like this:

| In the body | Effect on the lines |
|---|---|
| Absent | Left untouched |
| An array | All lines are replaced by the array, in its order, in one atomic write |
| `[]` | All lines are removed |

There's no way to change a single line: send the whole list.

**Responses:** 200 with the updated [Recipe](#recipe); 400 as for POST; 404 `{ "error": "Recipe not found." }`.

### `DELETE /api/recipes/:id`

Deletes the recipe and its lines. The ingredients themselves are kept.

**Responses:** 200 `{ "message": "Recipe deleted successfully." }`; 404 `{ "error": "Recipe not found." }`.

## Ingredients

### `GET /api/ingredients`

Lists ingredients. Takes `search`, `limit` and `offset` (see [Lists](#lists-search-and-pagination)).

**Responses:** 200 with an array of [Ingredient](#ingredient) and `X-Total-Count`; 400 for a bad query.

### `GET /api/ingredients/:id`

**Responses:** 200 with the [Ingredient](#ingredient); 404 `{ "error": "Ingredient not found." }`.

### `POST /api/ingredients`

| Field | Required | Rules |
|---|---|---|
| `name` | yes | String. Trimmed and lowercased, then 1–100 characters |

`{ "name": "  Red Onion " }` is stored as `"red onion"`.

**Responses:**
- 201 with the created [Ingredient](#ingredient)
- 400 for a missing, empty or over-long name, or an unknown field
- 409 `{ "error": "That name already exists." }`, after normalising: `"Onion"` clashes with an existing `"onion"`

### `PATCH /api/ingredients/:id`

Renames an ingredient. Takes the same body as POST; `name` is required.

**Responses:** 200 with the updated [Ingredient](#ingredient); 400 as for POST; 404 `{ "error": "Ingredient not found." }`; 409 `{ "error": "That name already exists." }`.

### `DELETE /api/ingredients/:id`

**Responses:**
- 200 `{ "message": "Ingredient deleted successfully." }`
- 404 `{ "error": "Ingredient not found." }`
- 409 `{ "error": "Cannot delete ingredient that is used in recipes." }`. Remove it from those recipes first.

## Units

A line's `unit` must be one of these symbols or aliases. Matching ignores case, spaces around the unit, repeated spaces and one trailing full stop, so `" Tbsp. "` becomes `tbsp`. Responses always use the symbol. Leave the unit out, or send null or `""`, for a count such as "3 eggs".

| Symbol | Aliases | Measures |
|---|---|---|
| `g` | gram, grams, gr | mass |
| `kg` | kilogram, kilograms, kgs | mass |
| `oz` | ounce, ounces | mass |
| `lb` | pound, pounds, lbs | mass |
| `ml` | millilitre, millilitres, milliliter, milliliters, mls | volume |
| `l` | litre, litres, liter, liters | volume |
| `tsp` | teaspoon, teaspoons, tsps | volume |
| `tbsp` | tablespoon, tablespoons, tbs, tbsps | volume |
| `cup` | cups | volume |
| `fl oz` | fluid ounce, fluid ounces, floz | volume |
| `pinch` | pinches | other |
| `clove` | cloves | other |
| `slice` | slices | other |
| `can` | cans, tin, tins | other |
| `bunch` | bunches | other |
| `handful` | handfuls | other |

An unknown unit is a 400 whose message lists the symbols. The list lives in `src/units.ts`; adding a unit is a code change, not a migration.

## Errors

Every error body has an `error` message. Validation errors add `fields`, with one message per field:

```json
{
  "error": "Validation failed.",
  "fields": {
    "servings": "Must be a whole number.",
    "ingredients.0.unit": "Unknown unit \"handfull\". Use one of: g, kg, oz, lb, ml, l, tsp, tbsp, cup, fl oz, pinch, clove, slice, can, bunch, handful, or none for a count.",
    "ingredients.1.quantityMax": "Only allowed when quantity is set.",
    "createdAt": "Unknown field."
  }
}
```

Nested fields use dotted paths: `ingredients.0.unit` is the first line's unit. A problem with the body as a whole, such as a missing body, is reported under `(input)`.

| Status | Meaning |
|---|---|
| 400 | Validation failed, the body isn't valid JSON (`"The request body is not valid JSON."`), or a recipe line names an ingredient that doesn't exist |
| 404 | The recipe or ingredient in the URL doesn't exist. Unknown routes also get a 404, but as Express's plain HTML page rather than JSON |
| 409 | An ingredient name is already taken, or an ingredient is still used by a recipe |
| 413 | The body is over 100 kB (`"request entity too large"`) |
| 500 | Something unexpected. The body is always `{ "error": "Internal server error" }`; details go only to the server log |
| 503 | Health check only: the database can't be reached |
